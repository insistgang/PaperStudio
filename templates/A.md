# A. 论文核心解剖与卖点提炼表

> **用途**：把问题、机制、I/O 链和最多 3 个硬核卖点压到一张可辩护的表。  
> **完成标准**：没看过代码的同行只凭本表能写出摘要 + 引言贡献条，且能指出关掉每个卖点时哪张表会变。  
> **口径**：[审稿人口径](../docs/reviewer.md) · [创新点判定标准](../docs/innovation.md)  
> **填写**：复制到 `papers/<短名>/A-解剖.md` 再填。方括号 `【】` 是填写位；示例斜体仅供对照，写完删掉。

## 1. 真实场景里的真问题（去包装）

> **指南**：用「谁、在什么图、哪类目标、哪一步失败、失败的代价」。禁止「精度有待提高」「鲁棒性不足」。

**使用方与决策**：【例：乡镇规划部门要在 0.5 m 卫星图上标新建建筑，漏检一处小彩钢房 = 漏管。】

**图像与目标的物理事实**（分辨率、目标像素跨度、正样本占比、干扰源）：

- 【分辨率 / 平台】
- 【目标典型尺寸（像素）】
- 【正样本占比】
- 【主要干扰：物候 / 阴影 / 配准残差 / 背景纹理 / …】

**可观察的失败模式**（必须能在可视化里指出来，写 1–3 条，每条一行）：

1. 【失败 A：例如「10–30 px 新建小屋，差分后响应被道路纹理淹没」】
2. 【失败 B】
3. 【失败 C】

**不是问题的问题**（写下来以免包装回去）：

- 【例：不追求在 ChangeFormer 量级上全面 SOTA；不把违建小样本塞进遥感 CD 引言。】

**一句话问题定义**（≤40 字，给摘要第一句用）：

> 【针对……失败，而不是针对「变化检测任务」。】

## 2. 输入—处理—输出逻辑链

> **指南**：审稿人会在脑子里跑一遍前向。张量写大概即可，但必须闭合。缺哪一步就补哪一步，禁止「然后经过深度学习网络得到结果」。

| 阶段 | 内容 | 形状 / 口径 |
|------|------|-------------|
| 输入 | 【双时相 RGB / 单帧 / 多光谱】 | 【H×W，是否已配准】 |
| 预处理 | 【裁块、归一化、增强】 | 【训练裁块尺寸】 |
| 编码器 | 【共享权重？骨干名？几个尺度？】 | 【C2–C5 或 P2–P5】 |
| 变化表征 | 【相减 / 拼接 / 相关 / 门控】 | 【在哪一层做】 |
| 解码 / 头 | 【FPN / 分割头 / 检测头】 | 【输出几类】 |
| 损失 | 【CE / Dice / Focal / 检测框损失】 | 【权重】 |
| 输出 | 【变化二值图 / 框+类】 | 【推理阈值】 |
| 部署输出（若有） | 【ONNX / TensorRT / 板端】 | 【硬件、精度、是否含前后处理】 |

**数据流一句话**：

> 【I1, I2 → 共享编码器四尺度 → 逐尺度差分 → 门控 → 解码 → 变化掩膜。】

**推理与训练不一致之处**（重参数化、TMA、测试增强）：

- 【无 / 有：训练多分支，推理融合为单路】

## 5. 卖点三元组（最多 3 条）

> **指南**：第 4 条默认是包装，删。每条必须过 [审稿人口径](../docs/reviewer.md) 的 10 秒测试，并按 [创新点判定标准](../docs/innovation.md) 定级。正文若写了 4 条贡献，本表仍最多认 3 条 L2，其余降级为方法细节。  
> **CSCD 允许窄**：归因、负向边界、板端实测都可以是卖点，只要可证伪。

### 卖点 1：【机制名，不要写「提出了 XXX 模块」】

- **一句话（≤25 字，给审稿人记）**：【】

- **适用边界 / 负向**：【在哪类数据上应变弱或关掉】
