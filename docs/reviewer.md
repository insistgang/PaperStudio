# 审稿人口径

> PaperStudio 的宪法。写任何贡献句、对比表、防守段之前先过这里。
> 口径来源：TGRS / PR / RS / 计算机学报 / 计算机工程 类审稿习惯，加上 知识库刘老师 8 条对照表 的现场教训。

---

## 审稿人实际在问的四件事

1. **你到底解决了哪个可观察的失败？** 不是「检测精度有待提高」。
2. **你的模块是为这个失败设计的，还是为了有东西可写？**
3. **证据是否同协议、可关掉、可复现？**
4. **代价说清楚了没有？** 精度换速度、换参数、换泛化，必须亮出来。

应用类中文刊（计算机工程、计算机应用）比顶会更吃第 4 条；SCI 2 区 / TGRS 把 1–3 咬死。顶会还要问：这个问题定义本身新不新。

---

## 十二条铁律

1. **贡献 ≠ 做了什么。** 「引入 RepViT」「加入差分门」是流水账。贡献必须是：新机制是什么 + 它带来的可验证益处。
2. **摘要里的痛点，引言必须展开。** 摘要写了「深浅层失衡 / 弱变化漏检 / 边缘实时受限」，正文却用「现有方法存在不足」一笔带过，直接被打回。
3. **相关工作要点名「死法」，不要点名「名单」。** 列出 FC-Siam、BIT、TinyCD 不够；要写它们在你的失败模式下哪一步失效。
4. **理论依据可以不是公式，但不能只挂文献号。** 转述 2–3 句机制，再接到你的设计。禁止「可能」。
5. **消融必须能证伪。** 三个模块各 +1 次不是消融；至少要有「去模块」和「更简单替代」。2×2 才能谈交互。
6. **公开数字 ≠ 你的对比实验。** 非同协议复现，表题写成「量级对照」，正文禁止「优于 XXX」。
7. **加粗同列最优，不加粗自己。** 自己全面落后时，价值只能改道：归因、边界、部署、失败分析。
8. **数据集不是「用了 LEVIR」。** 分辨率、区域、正样本占比、划分协议、与文献划分是否可横比，必须写。
9. **工程数字必须是实测口径。** 参数量 / FLOPs 是理论复杂度；FPS 必须写硬件、精度（FP16/FP32）、是否 TensorRT、是否含前后处理。
10. **跨数据集的负向结果是资产。** 藏起来会被审稿人当选择性报告；写清楚适用边界，CSCD 应用刊也认。
11. **自建集默认有偏置。** 标注者是否作者、类别定义是否事后改过、train/test 是否空间隔离，审稿人一定会问。
12. **语言确定性。** 用「旨在 / 用以 / 实验表明」，不用「可能 / 有望 / 在一定程度上显著提升」。

## 审稿人讨厌的十句空话（禁止出现在 A/B/C 和正文贡献条）

| 禁止 | 原因 | 替换方向 |
|------|------|----------|
| 提出一种高效鲁棒的方法 | 无机制、无数字 | 写出失败模式 + 模块名 + 指标 Δ |
| 融合了 CNN 与 Transformer 的优点 | 积木套话 | 写出各自负责的失败、交互如何验证 |
| 在多个数据集上均取得优越性能 | 往往有数据集掉点 | 分数据集报告，掉点当边界 |
| 大幅提升 / 显著优于 | 无统计、无协议 | 写百分点、写对照设置 |
| 填补了该领域空白 | 几乎永远假 | 写「尚未在 X 设定下报告 Y」 |
| 具有重要的理论意义和实用价值 | 正确的废话 | 删 |
| 端到端 | 2016 年以后不是卖点 | 删，除非对比两阶段流水线 |
| 即插即用 | 承认自己是积木 | 改成对指定检测器的受控植入实验 |
| 轻量级（无参数量） | 形容词 | 写 M / GFLOPs / ms |
| SOTA | 中文应用刊尤其危险 | 除非同协议全面第一，否则禁止 |

## 判断「这句能不能进引言贡献」的 10 秒测试

把贡献句读给一个没看过你代码的同行，问三句：

1. 你改的是哪一个计算步骤？
2. 关掉它，哪张表的哪一格会变？
3. 在哪类数据上你准备承认它没用？

三句都答得出，才能写进模板 A。否则降级为实现细节。
