# 期刊匹配梯度

> 配套 [模板 C](../templates/C.md)。
> 分区会变，本表给的是 **2026 年 CV / 遥感 / 检测应用稿的审稿口味**，不是最新 IF 排行榜。投前仍须核目标刊最新栏目与范文。

---

## 梯度定义（本系统专用，不是中科院分区复印件）

| 梯度 | 代表去处 | 最低创新级别 | 实验最低配置 | 对「不超 SOTA」的容忍 |
|------|----------|--------------|--------------|------------------------|
| G0 课程/报告 | 校内报告、普通普刊 | L0 | 单数据集、能跑通 | 极高，但没有学术筹码 |
| G1 中文核心偏应用 | 《科技和产业》类、部分核心应用栏目 | L1–L2 | 1 公开集 + 消融 | 高，但要有场景数字 |
| G2 CSCD / 中文核心计算机类 | 《计算机工程》《计算机应用》《计算机工程与应用》 | **L2** | 1–2 公开集 + 去模块消融 + 代价数字 | **可以不超 SOTA**，必须改道讲归因/部署/边界 |
| G3 中文一流学报 | 《计算机学报》《软件学报》《自动化学报》《遥感学报》 | L2 强或 L3 弱 | 多数据集 + 充分消融 + 失败分析 + 写作极干净 | 低。通常要接近或超过强基线 |
| G4 SCI 4–3 区应用 | *Remote Sensing* (MDPI)、*Sensors*、部分 *IEEE Access* | L2 | 双公开集 + 消融 + 最好有部署 | 中。Sensors 已有拒稿先例：应用包装压不住创新质疑 |
| G5 SCI 2 区遥感/视觉 | *IEEE JSTARS*、*IEEE GRSL*（短文）、部分 *ISPRS* 相关、*PR* 下游 | L2 强 | 多数据集、同协议复现、统计、开源加分 | 低 |
| G6 SCI 1 区 / 顶刊顶会 | *IEEE TGRS*、*ISPRS JPRS*、*PR*、CVPR/ICCV/ECCV | L3 或极强 L2 | SOTA 或新问题 + 完备消融 + 开源 | 极低 |

GRSL 是短文通道，方法必须极窄极干净，不是「把长文塞短」。

---

## 匹配规则（按稿件真实状态，不按野心）

按顺序问，先命中先定：

1. **只有换骨干 / 单数据集 / 无消融** → 最高 G1。停。
2. **积木 + 有消融但无机制差** → G1，冲击 G2 会被问「拼模块」。
3. **有 L2 机制、双数据集或 1 公开+1 自建、有代价数字，指标不超最强轻量基线** → **G2 是甜蜜点**。不要为了面子冲 G4。
4. **有 L2、同协议超过强基线、有失败分析** → 可评估 G3 / G4。
5. **有新问题定义或跨任务泛化证据、开源、多次种子** → 才讨论 G5+。

**禁止用目标期刊倒推创新。** 先定级，再匹配。E-PAS 已在 Sensors（G4）被拒，说明「应用+高 FPS」不够，必须先回模板 A 定级，再决定改 / 暂停 / 降梯度。

## 概率怎么写（禁止假精度）

模板 C 只允许四档，不允许「录用概率 73%」这种伪定量：

| 档 | 含义 |
|----|------|
| 高 | 按该刊近 2 年同类范文，当前证据包已达中位以上，主要风险在写作/格式 |
| 中 | 证据包够入审，但有 1–2 个必问死穴，补丁后可过 |
| 低 | 创新或实验明显低于该刊中位，强投大概率拒 |
| 极低 | 梯度错配或有一票否决项（协议不公、无消融、数据不可信） |

「有条件可投」= 目标梯度内、概率中或高，且必补实验清单可在投稿前关闭或诚实降声称。
